# 读者站写作规范

读者站 `site/`（VitePress，发布到 GitHub Pages `/docs/`）各章重写所依的规范。样章是民俗篇《干支历四柱》（`site/folk/ganzhi.md`），体例、深度、引文格式以它为准。

## 一、读者与定位

- 读者是想弄懂原理与源流的人，不是本项目的开发者。每章自成一体、按顺序读，不靠跳转；不写代码路径、函数名、文件名、数据文件名。
- 与知识库 `doc/` 分工：`doc/` 记实现、校验、代码路径；`site/` 讲原理、历史、各家。数字必须与 `doc/` 一致，`doc/` 里没有的数字不要自己编，先在 `doc/` 里补上并说明来源。
- 不写本项目的 bug 与修正经过（"原先错了、后来改了"之类）。各模型、各拟合目标、各方法之间的精度比较，速度与精度的权衡，要保留。

## 二、内容要求

目标是"广收各家"，不是只讲本项目怎么做：

1. **原理与推导**：给出公式的来历，能推导的推导，不只抛结论。口诀、算法、经验公式都要说明它为什么成立（如五虎遁由 6g − 5z 推出）。
2. **源流（发展史）**：这一学说、理论、方法怎么来的，谁先提出，后来怎么演变，各阶段的代表人物、代表著作、代表模型。中西都有的（如岁差：虞喜／喜帕恰斯，到 Newcomb、IAU 1976、P03、Vondrák）都要写。
3. **各家并列**：凡有分歧的地方，各派做法并列成表，注明出处，不替读者取舍；能用证据判定优劣的（精度、实测）给出比较数字。
4. **本项目的取法**：放在章末，简短说明本项目用哪一家、为什么、精度多少、还缺什么。
5. **参考文献**：章末编号列出。

## 三、引文与考据

- **能核原文的一律核原文**，引文逐字照录，注到书名、卷、篇名（或页码），版本写在参考文献里。
- 资料可靠性次序：实物历日 > 史书明载日期 > 史志所载术文 > 按术文推算 > 今人历表 > 天文计算（问天象时天文计算最高）。证据只能由上往下检验。今人复原表不是史实。
- **业余整理来源降权**：廖育栋（ChineseCalendar）、许剑伟（寿星天文历）是业余整理者，不是专业学者。两人只作数据转录或对照来源，称"业余整理"，不列入学术源流表；论断以他们所据的原书为准（张培瑜、万国鼎、李崇智等）；他们独有的统计、假定、人工修正，注明"据某某，未独立核对"或"无史料依据"。
- 没有核到原书的，在引文旁注明"转引自某书""据今人录文，未核原书"；推断要写成推断（"当指""待考"），不写成定论。
- 原文录文有讹字，按文义改正时要说明改了哪里。
- **原典的存放**：
  - 体积小、公有领域的录文放 `vendor/<领域>/`（例：`vendor/folk/wikisource/`），原样保存，目录下 README 记来源、取得日期与方法；
  - 书影、扫描 PDF 体积大，放 `doc/references/<领域>/`（已 gitignore，不入库），在相应 README 里记路径与页序；
  - 中华书局点校本二十四史扫描在 `doc/references/history/`，按需读页，注明册与页。
- **取原典的门路**（已验证可用）：
  - 维基文库：MediaWiki API `action=raw` 取 wikitext，`list=search&srsearch=intitle:...` 找四库本；
  - archive.org：`advancedsearch.php` 检索，`/download/<id>/page/n<N>_w1000.jpg` 按页取图；大文件用 `aria2c -c -x16 -s16`；
  - ctext.org 拒绝自动访问；来源不明、繁简混杂的录文不用。
- 天文方面的论文、IERS 规范、IAU 决议等，优先引原始论文（作者、年份、刊名、卷页），已有的 PDF 在 `doc/references/` 下各子目录。

## 四、体例

- 章名：一个词，至多两三个词，不加副标题；意思不能为凑字数而丢失。改章名、改目录先给用户审核。
- 章内一级小节用"一、二、三……"编号（见样章）；引文用块引用 `>`，正文里的短引用用中文引号。
- 古籍引文保持原书字形（繁体、异体照录）；正文叙述用简体。
- 配图、动画用 Manim 本地渲染（`scripts/manim/`），要用真实几何；统计图数据由 `scripts/figures/` 生成。
- 写完必须 `cd site && mise exec -- npx vitepress build` 通过。

## 五、生成页的处理

天象（日月食、行星、恒星与二十八宿、当地星空、史书天象检验）、历法（实历与主表、历代历法总录、各朝推步、秦与汉初历法）各章，目前由 `scripts/figures/build_site_pages.py` 从 `doc/` 生成。重写这些章时：

- 改为手写页，从 `build_site_pages.py` 中去掉该章的生成，并更新 `scripts/figures/README.md`；
- 其中逐条数据表（例：各次日食的检验结果）仍应由脚本生成，放到附录或以 `<Chart>` 引用，不手抄；
- 附录各页（天象逐条校验、本纪核验主表、历法原文摘录）保持生成，不在本次重写范围内。

## 六、协作

- 多个会话共用同一工作树：只改自己领到的章节文件，`git add` 只写明确路径，不用 `git add -A`（根目录常放有不入库的书）。
- 改到共享文件（`site/.vitepress/config.mts`、`build_site_pages.py`、`scripts/figures/README.md`、本规范）时先 `git pull`/看 `git status`，改动尽量小，提交要快。
- 每写完一章单独提交，提交信息中文，说明这一章补了哪些源流、哪些原典、还有哪些转引待核。
- 推送（发布）前先问用户。
