# 网页交互设计：时空上下文与分层呈现

本文记网页（`web/`）交互的整体设计、现状问题与分期改造。各页细节仍见 [web-folk-pages.md](web-folk-pages.md)。

## 一、现状问题（2026-11-09 逐页截图，桌面 1366 与手机 390 宽）

| 问题 | 表现 |
|---|---|
| 时刻、地点各页各管 | 日历右栏有一套年月日时选择；择日、排盘各有「前一日/后一日/实时」条；星图自有日期输入与地点（缺省长安 108.94E，与他页的北京定位不一致）；日月食按年查。用户在日历选定某日后去星图，看到的是另一时刻、另一地点 |
| 导航混入工程工具 | 顶栏第二项是「视位置变换图」（坐标变换图，开发用），排在星图、择日前；页脚常驻历表加载状态 |
| 手机宽度溢出 | 六页在 390 宽下页面实宽 762—786，导航条不换行，整页横向滚动 |
| 结论淹没在依据与设置里 | 排盘页盘下十余排同权重的起例按钮；择日婚嫁三十行长文，可用与否在行首小字，制化说明整段红字；日历左栏宜忌、更点成片 |
| 盘面与文字不联动 | 格局写「白虎猖狂（1宫）」，要自己去盘上找一宫；点盘上某宫没有反应 |
| 状态不能分享 | 视图、页签、时刻都不在网址里，刷新回到首页今日，无法把「某日某时的六壬课」发给别人 |

## 二、核心模型：一个时空上下文

所有页面看的是同一个「此时此地」：

- **时刻**：民用历日期 + 时分秒（时区为所选时区）；或「实时」（随当前时刻走）。
- **地点**：经纬度（定位或手填）；磁偏角由此派生。

时刻与地点只存一份（`App`），放在常驻顶栏里显示与修改；各页只读它，或经回调写它（如择日「后一日」、星图「播放」、日食表点选某食）。每页按自己的粒度给步进键：

| 页 | 步进 |
|---|---|
| 日历 | 月、日 |
| 择日 | 月（婚嫁按月）、日 |
| 排盘 | 日、时辰 |
| 星图 | 时、日（播放即连续步进） |
| 日月食 | 选一食即跳到其食甚 |

**为什么**：用户的典型路径是串起来的——在日历选一日 → 看宜忌 → 去择日看年神方位与婚嫁 → 去排盘看当时的盘 → 去星图看当时的天象。每一步换页都应当保留「此时此地」，不必重选。

## 三、网址即状态

`#/<页>[/<页签>]?t=<年>-<月>-<日>T<时>:<分>&lat=<纬>&lon=<经>`

- 无 `t` 即实时。年用天文纪年（0 为前 1 年，可负），日期为民用历（1582-10-15 前儒略历），与日历所示一致。
- 换页、换页签记入浏览历史（可后退）；改时刻只替换当前记录（不把每次步进塞进历史）。
- 打开带参数的网址即复原同一视图：可把「某日某时的六壬课」作链接分享。
- 经纬度在网址里只留两位小数（约 1 公里），分享链接不暴露精确定位；与本机所存者相差不到 0.005° 时仍用本机所存。

## 四、每页三层：结论 → 依据 → 设置

1. **结论**在上：盘面、局、可用与否、宜忌。
2. **依据**随结论可展开：格局出处、神煞来由、逐条否决理由。
3. **设置**（起例、流派）收进「起例」区（各盘所选记于本机 localStorage，下次打开沿用；「恢复缺省」一键回到有据之缺省），平时只显示一行摘要，如「依协纪（缺省）· 已改 2 项 · 重置」；展开后才是逐项选项。各家并列、缺省有据的原则不变，只是不再与结论同权重铺开。
4. **说明与出处**（长段灰字）收进可展开的「说明」。

区分「设置」与「输入」：本命生年、流年、坐山、女命生年等是这一问的输入，留在外面；时家/日家、岁计/时计、十四主星/十八飞星派是「看哪一种盘」，也留在外面；只有同一盘的异说取舍（定局、寄宫、贵人、换将……）进起例区。

## 五、联动

- 盘面 ⇄ 文字：点盘上一宫，列出该宫诸项与相关格局；点文字中的格局或「某宫」，盘上高亮对应宫位。
- 婚嫁择吉以月格呈现：可用日着色，点日看逐条理由；同一组件可作日历的「择吉」图层。

## 六、手机

- 顶栏只留时空条（◀ 时刻 ▶、实时、地点）；页面导航改为底部标签栏（五项 + 更多）。
- 不得横向溢出：盘面随宽缩放，选项控件可换行，固定宽度的栏改为流式。
